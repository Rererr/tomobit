## Context

ADR-0012 Decision 3 は「**名誉回復は減衰だけで行う — 忘却が寛容を生む**」と置いた。
較正もその前提でなされている（`decide.go`: 一様事前 Beta(1,1) の q20 はちょうど q なので
「新鮮な1敗は約3半減期で再入場」）。

ADR-0013 が「忘却の底は白紙ではなく**家系の記憶**」へ変えたとき、この較正は見直されなかった。

Split の子は親の事後平均 μ を継いだ事前 Beta(μ·m₀, (1−μ)·m₀) を持ち、
減衰はその事前へ沈む。実測（完全減衰＝事前そのものの q20 とゲート通過）:

```text
mu=0.05 → Beta(0.100,1.900) q20=0.0000 pass=false
mu=0.30 → Beta(0.600,1.400) q20=0.0470 pass=false
mu=0.40 → Beta(0.800,1.200) q20=0.1114 pass=false
mu=0.50 → Beta(1.000,1.000) q20=0.2000 pass=true
```

**親の事後平均が概ね 0.48 未満のときに生まれた子は、何年経ってもゲートを通らない。**
減衰は事前へ向かうだけで、事前そのものがゲートの下にあるからである。

しかも自己強化する。ゲート落ちした Provider はその scope で選ばれない →
その scope の経験が来ない → 子の Connection は `judge` に触れられない →
**merge の判定機会そのものが訪れない**。
`judge` の merge チェックは、その経験で触れられた Connection にしか走らないためである。
能動探索の逃げ道も無い: `curiosity.Gaps` は NMin=2.5 の証拠と ln BF 中立帯を要求するので、
恒久ゲート落ちの子は Preference Gap にも duel にもならない。

結果として ADR-0012 Decision 3 の約束が、継承事前を導入した scope では成立していない。

---

## Decision 1: ゲートの式も継承事前の式も変えない

`decide` の悲観ゲート（`Quantile(0.20) ≥ 0.20 − 0.02`）と
`Engine.split` の継承事前（μ だけ継ぐ）は、どちらも無改変とする。

却下した対案を先に置く:

- **ゲートを priorA/priorB 相対に自己参照化する**（「事前と同等なら通す」）→
  ADR-0012 の明文（基準線は自己参照）には忠実だが、
  μ=0.05 の親から生まれた子まで完全減衰後に通過してしまい、
  **能力ゲートの意味（無知以下を通さない）が家系ごとに緩む**。
  ゲートは「この相棒はこの仕事をやれるか」の線であって、家系の内輪の基準ではない
- **継承する μ を下限クリップする** → ADR-0013 Decision 1 の
  「平均だけ継ぐ」という純度に第二のノブを持ち込む。
  ノブが増えるとき較正の説明責任も増える — ここで払う価値は無い

## Decision 2: 名誉回復は merge が担う — 判定を全ての子へ到達させる

救済は既に設計の中にある。子の distinguishing token の ln BF は証拠の減衰とともに 0 へ向かい、
`ThetaMerge` を下回れば `judge` は子を畳む。子が消えれば親（根なら Beta(1,1)）が読まれ、
q20 = 0.20 でゲートを通る。**ADR-0012 Decision 3 も ADR-0013 Decision 1 も無改変のまま
「忘却が寛容を生む」が復活する。**

欠けているのは判定の**機会**だけである。したがって:

- merge の判定を「その経験で触れられた Connection」に限定しない。
  **子を持つ系譜に対して、触れられたかどうかと独立に merge 判定が届く**ようにする
- merge 判定は decayed evidence の純関数であり、いつ評価しても答えは同じ
  （評価の時刻だけが入力）。したがってこれは**意味論の変更ではなく到達性の修復**である。
  θ も台帳の寿命も触らない
- 評価の頻度はコストで決める。経験1件ごとに全子孫を走査するのは
  ADR-0002 が「第二段: 審判（重い、呼ばれた時だけ）」と置いた規律に反する。
  **Apply のバッチ境界と Rebuild で1回**が上限であり、
  そのコストが許容できる形（`matchingExperiences` の重複除去・経験のキャッシュ）を
  同時に用意すること

## Decision 3: 較正コメントに但し書きを入れる

`decide.go` の「新鮮な1敗は約3半減期で再入場」は**一様事前を前提にした数値**である。
継承事前の下では成立しないので、その旨と、名誉回復が merge 経由で成立することを
コメントに明記する。ADR-0012 Decision 3 にも本ADRへの改版参照を追記する。

数値を書いたコメントが前提を書いていないと、次に読む人が同じ穴を再発見できない。

## Consequences

- 継承事前で生まれ、その後使われなくなった子は、証拠の減衰とともに畳まれ、
  親が読まれるようになる。ADR-0012 Decision 3 の「忘却が寛容を生む」が
  継承事前の下でも成立する
- ADR-0036（Task Perception の配線）の前提条件が満たされる。
  配線した瞬間に Split 子が判断へ効き始めるため、**本ADRが先に要る**
- 「そのターゲットが一切使われなくなった場合」も merge 判定は届く（到達性が独立になったため）。
  ただし畳んだ後に親も使われなければ、親自身の減衰は ADR-0012 の一様事前の規律に戻る
  — これは元の設計どおりの姿である
- Rebuild の決定性は不変。merge 判定は decayed evidence の純関数なので、
  同じ台帳・同じ時刻から同じ結果に落ちる
