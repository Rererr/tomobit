## Context

ADR-0028 の N=20 計測レビューが2つの宿題を出した。子の無信号は
[ADR-0054](ADR-0054-a-child-is-the-breakdown.md) が閉じた。**残っていたのが
「並走が構造的に発動していない」**である。

```text
分割          20件中4件（20%）
うち独立群あり  3件（15%）
並走の実績      0回 — parallel_offered が3/3で false（提示すらされていない）
総額           $613.32
```

原因は1行で特定できる:

```go
func parallelGate(..., interactive bool, ...) (offered, accepted bool) {
	if !interactive || !declaresGroups(groups) {
		return false, false
	}
```

`interactive` は stdin と stdout の**両方**が TTY であること。`--view ndjson` は
stdout を非TTYに強制する（`validateViewFlag`）ので、**GUI では構造的に永久に
false** になる。境界の器官はすべて `humanPresent`（TTY または宣言された view
ストリーム — ADR-0035 Decision 2）を使っており、**並走ゲートだけが `interactive`
に取り残されていた。**

### 所有者の観察が、問いの形を変えた（2026-07-27）

「ゲートを GUI へ通すか」を壁打ちしたところ、所有者から実際の使い方が出た:

> 四窓あれば、四つ別のタスクを行いたい（…）「メインの機能の大規模リファクタ
> （αとβの修正）をしたい」タスクで、Aの窓には「αを着手」Bの窓には「βを着手」
> みたいな使い方をする人はそういない。**Providerの先のLLMが賢い前提だから、
> 絶対に「メインの機能の大規模リファクタをしたい」ってそのまま投げる**

これで2つのことが決まった。

**軸が2本あって、混ざっていた:**

```text
窓の軸     4つの別タスク       作業場は別で当然   → 解決済み（GUI ADR-0009 / ADR-0054 D3）
分割の軸   1タスクの中の内訳    作業場は同じ       → ここだけが未解決
```

窓をいくら増やしても**1つの大きなタスクは1ミリも速くならない**。1タスクの中で
同時に動ける経路は分割の並走だけであり、そこを閉じれば大規模リファクタは永久に
逐次になる。**起草者が壁打ちで出した対案「並走の単位を窓にする」は、人が
やらないと言われた形そのものだったので却下された。**

**そして残った問いは1つだけになった: Provider の「この2つは独立だ」を信じるか。**

---

## Decision 1: 信じる。宣言された独立群は、訊かずに並走する

`parallelGate` を撤回する。Provider が独立と宣言した群は、人に訊かずに並走する。

理由は3つ。

### 1. 一貫性 — 丸投げの相手を、分け方でだけ疑う根拠が無い

所有者の観察のとおり、人は大規模リファクタを**丸ごと**この Provider に任せる。
その同じ相手の「αとβは独立だ」だけを人が査読する、というのが旧設計だった。
**分割の中身を信じて丸投げしておいて、分け方だけ疑うのは一貫していない。**

### 2. ゲートは、答えられない人に訊いていた

人はサブタスク文を読んでいないし、独立かどうかを判断する材料も持っていない。
y/N を押しても、それは同意ではなく**手間の増えたコイントス**である。
[ADR-0011](ADR-0011-meaning-by-model-judgment-by-math.md) の線で言えば、
独立かどうかは**意味**の問題で、モデルの席にある。人の席に置いたのが誤りだった。

### 3. 信じて失敗したことが、正直に観測される

[ADR-0054](ADR-0054-a-child-is-the-breakdown.md) が子の経験を消したので、
**踏み合って壊れた並走の子は、もう Beta を1ミリも動かさない**。壊れるのは
成果物だけで、台帳は汚れない。そして壊れた成果物は:

- 境界の第1層（[ADR-0052](ADR-0052-first-layer-is-observed.md)）で赤くなる
- 人が「3=だめだった」と言う
- どちらも**親の経験に乗る**

**信じた結果が、信じた本人（親のタスク）の成績として返ってくる。** これは
学習の外に落ちる失敗ではない。

### 検証はしない、という線は動かない

tomobit は独立宣言を検証できない。[ADR-0050](ADR-0050-workspace-isolation-protocol.md)
Decision 2 が隔離について書いたのと同じ形である。違いは、隔離の
`isolated:false` が正直で無害なのに対し、**独立宣言の誤りは成果物を壊す**こと。
本ADRはその差を承知の上で、上の3つを理由に信じる側へ倒す。

---

## Decision 2: 費用は訊かずに、始める前に1行言う

ゲートが消えると、旧ゲート文が出していた概算コスト（直近実測の中央値 × 並走幅）
の出し場所が無くなる。**K倍の費用が事前に見えないまま増えるのは、独立宣言を
信じることとは別の問題**なので、そこは残す — ただし**問いではなく事実として**。

```text
これまで  「独立宣言された2本を並走できる — 並走する? （概算 $0.42）[y/N] 」
これから  「-- group 2/3: 2本を並走（概算 $0.42 = 直近実測の中央値 × 2本）--」
```

GUI [ADR-0009](https://github.com/Rererr/tomobit-gui/blob/main/docs/decisions/ADR-0009-four-panes.md)
が「同じ場所で働く窓があることは**判断せず事実として言う**」と決めたのと同じ姿勢
である。概算が取れない（費用を報せる実行がまだ無い）ときは黙って幅だけ言う —
[ADR-0028](ADR-0028-auto-split-parallel.md) Decision 3 の
「作り話の金額を出さない」はそのまま生きている。

---

## Decision 3: kill switch は置く — 信じることと、止められることは別

config `parallel_subtasks`（bool・既定 true）を足す。`split_protocol` /
`isolate_protocol` と同じ形（ポインタ、nil = 既定ON なので、このキーを知らない
config が黙って降格しない）。

信じる側へ倒したことと、実運用で困ったときに止められることは別の話である。
兄弟の常時ONプロトコル2本が同じ弁を持っているので、ここだけ持たない理由が無い。

`parallelWidthCap`（初期3）は不変。5本宣言されても3本ずつ走る — 同時に立つ
CLI の数の上限であって、信じるかどうかとは無関係の実装ノブである。

---

## Decision 4: `task.split` の payload から、ゲートの2キーを落とす

```text
これまで  {"subtasks":[...], "groups":[[...]], "parallel_offered":false,
           "parallel_accepted":false, "est_cost_usd":0.42}
これから  {"subtasks":[...], "groups":[[...]], "est_cost_usd":0.42}
```

`parallel_offered` / `parallel_accepted` は提示と回答の記録であり、提示も回答も
無くなったので**記帳をやめる**。`false` を書き続けるのは「提示したが断られた」と
読める嘘になる。

**並走したかどうかは `groups` から導出できる**（2要素以上の群があれば並走した）
ので、新しいキーは足さない。`est_cost_usd` は残す — 人へ言った数字を記帳する、
という ADR-0028 の規律（「ゲートで見せた数と task.split の数が食い違わない」）は
文言が問いから事実に変わっても同じである。

**過去の行は書き換えない**（One Ledger）。計測レビューの読み手は、両キーを持つ
古い行と持たない新しい行の両方を読めるようにする。

## Consequences

- **`interactive` を読む問いが1つも無くなった。** 境界の器官はすべて
  `humanPresent`、権限は view ストリーム、並走は訊かない。`interactive` は
  この後 chat の他の用途にだけ残る
- **GUI から初めて並走が起きる。** 実運用の入口が GUI である以上、
  「分割の15%で並走が発動する」が今日から実態になる
- **並走の子の出力は、view ストリームでは note 行として届く。**
  `splitSink` が `[2:claude-code] …` と前置きした行が、そのまま noteWriter を
  通って `{"type":"note"}` になる。端末で見えているものと同じで、**どの
  サブタスクの発言かは読めるが、型付きの吹き出しにはならない** — 逐次の子が
  持つ view フレーム（`newSubtaskView`）を並走の子は持たない。
  **これは既知の劣化であり、隠さない**（下記「残った宿題」）
- ADR-0028 の Decision 2（群宣言）・Decision 4（群間逐次・群内並走・fail-stop）は
  **不変**。変わったのは「群内並走に入る条件」だけである
- SCHEMA.md R4 の `task.split` の説明を更新する

### 残った宿題: 並走の子の view フレーム

逐次の子は `newSubtaskView` で自分のフレーム（`turn.started` / `text` /
`turn.finished`）を持つ。並走の子は持てない — `ndjsonView` の出す型に**どの子の
発言かを載せる場所が無い**ので、K本が同時に emit するとフレームが混ざる。

正しい解は、view のイベントに子の相関キー（窓が `pane` で相関しているのと同じ形）を
足し、GUI 側で並べて描くこと。**本ADRの範囲外**で、工数の実体は GUI 側にある —
GUI ADR-0009 の続きとして扱う。それまでは note 行で読める状態を維持する。

---

## 却下した対案

### ゲートを `humanPresent` へ差し替えて、GUI へ通す

壁打ちの「半信半疑」の立場。実装は最も重い（並走の view フレームが**先に**要る
——訊いて y と答えた直後に読めない出力が流れるのは、訊いた意味が無い）。
そして Decision 1 の理由2がそのまま効く: **通しても、人は答えられない。**

### 常時逐次を仕様と認め、Decision 3/4 を撤回する

壁打ちの「信じない」の立場。ゲートを消す点は本ADRと同じで、倒す向きが逆。
所有者は信じる側を選んだ。記録として、この立場が持っていた強みは
「同じ作業ツリーに2人の書き手を立てない」という**一点の明快さ**である —
もし並走の失敗が実測で目立つようになったら、`parallel_subtasks=false` が
そのままこの立場になる。

### 並走の単位を窓にする（人が窓を開いて分ける）

起草者が壁打ちで出した対案。**所有者の観察が直接否定した** — 人は大規模タスクを
分けずに丸ごと投げる。加えて、これは分割の采配を人へ差し戻すことであり、
「Provider が分けて、tomobit は運ぶ」という ADR-0023 以来の役割分担も崩す。

## 実測（2026-07-27・claude-opus-5・使い捨て台帳と使い捨て git リポジトリ）

**GUI と同じ入口**（`--view ndjson`＝非TTY、誰も端末に居ない）で、実 Provider に
「互いに完全に独立した3つのサブシステムをゼロから実装して」を投げた。

```text
提案      task.split {"groups":[[0,1,2]], "est_cost_usd":0.6233835,
                      "subtasks":[csvstat, httpecho, wordfreq]}
告知      -- group 1/1: 3本を並走（概算 $0.62 = 直近実測の中央値 × 並走幅）--
子の起動  provider.selected × 3
          …402213 / …402247 / …402266 ms  ← 47ms 以内に3本
```

- **旧設計なら1本も並走しなかった入口である。** `interactive` が false なので
  ゲートは立たず、3本は逐次に落ちていた。実測の「並走0回」がそのまま再現される
  条件で、**初めて並走した**
- **`parallel_offered` / `parallel_accepted` は記帳されていない**（Decision 4）。
  `groups` と `est_cost_usd` だけが残り、並走したことは `groups` から読める
- **告知は告知だった**: `[y/N]` は出ず、読み取りも起きず、行が出た直後に3本が
  立っている。人へ言った $0.62 と `task.split` の `est_cost_usd` は同じ数
- **子の出力はラベル付きの note で届いた**: `[2:claude-code] I'll start by …`。
  Consequences に書いた既知の劣化がそのまま観測された — どの子の発言かは読めるが
  型付きではない

この確認は**途中で打ち切った**（検証プロセス側の2分の上限に当たった。tomobit や
Provider の失敗ではない）ので、**群の走り切りと fail-stop の実 Provider での確認は
まだ**である。そこはユニットテスト（`markerFailAdapter` を使う W2/W3a）でピンして
あるが、実機ではない。

費用: 親 $0.21 + 打ち切られた子3本。同日の予備の2回（分割されなかった opus 1回と
「分割は不要」と判断した haiku 1回）を含めて、合計 **~$0.8**。

**haiku は同じ形の小さい依頼を「3つのユーティリティは完全に独立しており、1回の
実行で実現可能です。分割は不要」と判断した。** 分割はモデルの判断であり、常に
起きるわけではない（ADR-0028 Decision 1 の「判断はProviderに置く」がそのまま
観測された）。

## 実測（2026-07-27・GUI から実分割を1回・claude-opus-5・総額 $3.11）

本ADRの判定点（並走が実際に発動した分割5件）の**1件目**。使い捨て台帳・使い捨て
git リポジトリ・GUI の窓から、人が実際に打つのと同じ経路で流した。

```text
提案    task.split {"groups":[[0,1,2]], "est_cost_usd":0.5466}
子の起動  provider.selected ×3 → 114ms 以内に3本
成果    tools/csvstat/ tools/httpecho/ tools/wordfreq/
        それぞれ実装・unittest・README が揃った
検証    3本とも python -m unittest が OK
```

**独立宣言は当たっていた。** 3本は互いのディレクトリに1バイトも書いておらず、
テストも全て通る。**判定点の1件目は「壊れなかった」**である。

副産物として、同日の別の実行が ADR-0050 の「未確認」をもう1つ潰した:
`--provider auto` が codex を選んだ回、codex は分割せず1ターンで作業し、
**`isolated:false` を正直に返した**:

```json
{"isolated":false,"reason":"Gitの共通.git配下へのworktreeメタデータ作成が環境制限で拒否されたため"}
```

ADR-0050 Decision 2 が「隔離できない現場のために正直な出口を用意する」と書いた
経路が、実際にその形で使われた。

**GUI の画面上で並走のフレームを目視するところまでは届かなかった。** 検証を
毎回新しいブラウザページから駆動しており、ライブの描画状態はページの中にあるので
再現できない（スクロールバックも既定で無効だった）。フレームの描画自体は
[GUI ADR-0011](https://github.com/Rererr/tomobit-gui/blob/main/docs/decisions/ADR-0011-parallel-subtask-frames.md)
が同じイベント形で実測している — **実データと実描画を同じ1回で見る**のは、
窓を開いたままにできる次の機会に回す。

費用の内訳で1つ正直に: 締めの手順を誤って `1` を新しいターンとして送ってしまい、
1ターン分を無駄にした（chat はタスクを `/new` か `/exit` まで閉じない）。
$3.11 にはその分が含まれる。
