## Context

Provider 並走・Adapter 差分・Provider 能力の扱いを詰める過程で、同じ問題を先に
解いている外部実装（langchain, MIT）を読んだ。5件の候補が挙がったが、
そこで問われたのは「どれが良いか」ではなく **「読んだものを、どこまで持ち帰ってよいか」** だった。

前例はある。[ADR-0044](ADR-0044-provider-quota-observation.md) は CodexBar（MIT）を
着想元と明記し、「もらったのは経路の存在と仕組みだけで、コードは独立実装」と書いた。
あれで足りていた。ただし**規律は文書化されていない** — あのときは1件だったので、
起草者の作法で済んだ。今回は5件を同時に検討し、しかも参照元のソースを実際に開いている。
作法のままにしておくと、次に読むときの基準が起草者の記憶にしか無い。

ライセンスの事実（2026-07-30、一次資料で確認）:

| 対象 | ライセンス | 根拠 |
|---|---|---|
| langchain ルート | MIT (c) LangChain, Inc. | `LICENSE` |
| `libs/core` / `standard-tests` / `model-profiles` | MIT | 各 `pyproject.toml` の宣言。**LICENSE ファイルは無い**（HTTP 404） |
| `libs/partners/*` | MIT (c) 2023 LangChain, Inc. | 各 `LICENSE` |
| models.dev（`model-profiles` のデータ源） | MIT (c) 2025 models.dev | リポジトリ `LICENSE` |
| tomobit / tomobit-gui | **AGPL-3.0** | 各 `LICENSE` |
| tomobit `docs/` | **CC BY-SA 4.0** | `LICENSE-docs` |

方向は適法である。MIT を AGPL の成果物へ取り込むのは許される（逆は許されない）。
**危険はライセンスの非互換ではなく、無表示のコピーと翻案のほうにある。**
そして Python から Go への書き直しは、翻案であることの免罪符にならない。

判定は独立2系統で行った（起草者と codex）。結論は一致し、「パターン参照だから
帰属は常に不要」という起草者の当初の言い方だけが崩された。

---

## Decision 1: 借りるのは発想だけ。表現は持ち込まない

持ち帰ってよいのは、**何を決めるべきかという発想と、責務の分け方**だけである。
次のものは持ち込まない:

- コード片、docstring、コメント
- 識別子 — 型名・関数名・フィールド名・定数名
- 既定値、閾値
- テストケースの選択と配列、fixture、期待値
- データ（モデル一覧、能力値）

著作権が保護するのは表現であってアイデアではない。だから発想の借用に許諾は要らない。
一方で、テストスイートは**ケースの選択と配列**に、型は**フィールドの組み合わせ**に
表現がある。「機能的だから著作物性は薄い」は、同じにしてよい根拠にはならない。

帰属表記が要るのは**表現を持ち込んだときだけ**である。そのときは
`THIRD_PARTY_NOTICES.md`、`licenses/` にライセンス全文、当該ファイル冒頭に
由来と改変日を置く。**予防的に先に置かない** — 置いても翻案は正当化されないし、
「表現は持ち込んでいない」という本ADRの前提と矛盾した記録が残る。

## Decision 2: 読む工程と書く工程を分ける — 手続きで示す

参照元を読む工程（調査）と Go を書く工程（実装）を分ける。
**実装の入力は ADR に日本語で書いた仕様だけ**とし、参照元のファイルを開いたまま
実装しない。差分を取らない。

これは法的要件ではない。後から「写していない」と説明できる状態を、
記憶ではなく手続きで持つためである。ADR に仕様を書き起こす手間は、
この規律の代金であると同時に、**コード=How / テストコード=What** の責務分担
そのものでもあるので、二重の出費ではない。

今回の申告（誰が何を読んだかを残す）:

- **読んだ**: 入場制御・使用量集計・履歴編集にあたる3ファイル。
  → 実装前に本ADR系列へ日本語仕様として書き起こす（[ADR-0059](ADR-0059-admission-is-counted-by-the-machine.md) がその1件目）
- **読んでいない**: 適合試験パッケージ、能力宣言パッケージの各ソース。
  → 構成の発想だけを Decision 4 の採否に使い、実装は tomobit の契約から起こす

## Decision 3: docs には転載しない。着想元は1行で示す

`docs/` は CC BY-SA 4.0 である。MIT 由来の文章やコード片をここへ混ぜると、
MIT の表示保持義務と BY-SA の同一条件許諾を突き合わせる整理が要る。
**転載しなければ、その整理自体が要らない。** 短い引用は適法になりうるが、
適法性の判断を毎回抱えるより、自分の言葉で書いて原典へリンクするほうが安い。

形式は ADR-0044 のものを踏襲する:

```markdown
- 着想元: [名前](URL)（ライセンス, 権利者）。
  もらったのは〈何〉だけで、コードは独立実装（`パス`）
```

## Decision 4: langchain からの採否

| # | 発想 | 採否 | 理由 |
|---|---|---|---|
| 1 | Provider 起動の入場制御 | **採る（最優先）** | 機械全体で並走が数えられていない穴が実在する → [ADR-0059](ADR-0059-admission-is-counted-by-the-machine.md) |
| 2 | Adapter の共通契約試験 | **採る（実装時に別ADR）** | 規約が `executor.go` のコメントに散っている。ただし**独立配布パッケージにはしない** — Adapter は2つで内部実装のみ、外部統合向けの器は過剰 |
| 3 | Adapter 差の宣言 | **条件付きで採る** | 対象は UI・設定・試験が参照する差だけ（再開・許可・費用/トークンの観測・残量・作業場所）。**「できる」と「今回観測できた」を分け、不明と出所を持つ**こと（ADR-0044/0049 の正直さ）。モデル能力一覧の移植は不適合 — tomobit の Provider は API モデルではなく CLI である |
| 4 | 実行単位の測定値の正規化 | **縮小して採る** | claude-code は費用を、codex はトークン内訳を返す非対称が既にある。**欠損を欠損のまま持つ記録**だけを先に決め、集計UIは要る理由が出てから |
| 5 | 履歴のプレースホルダ置換 | **採らない** | 次回入力へ会話配列を再構成する発想であり、tomobit は Provider 固有の継続機構を使う。ツール出力は台帳に載せず表示は畳む（ADR-0031）ので責務は既に分かれている |
| — | エラー時の固定 fallback | **採らない** | 失敗は台帳に載るべき経験である。固定の連鎖は ADR-0012 の学習を迂回する |
| — | 依存関係つき DAG | **採らない** | ADR-0028 が却下済み。VISION の not an orchestrator に正面から反する |
| — | 汎用 middleware / 実行抽象 | **採らない** | 現在の責務境界で足りている。例外は #1 だが、あれは実行器前段の単一責務であって汎用スタックではない |
| — | Memory / VectorStore | **採らない** | Connection Engine と二重の知識体系になる |

※ #1 を具体化した [ADR-0059](ADR-0059-admission-is-counted-by-the-machine.md) は
2026-08-08 に却下された。**穴は数えたが、被害は観測されていなかった** — 手動では
同等以上の本数が日常的に立っている。発想としての採否は、逼迫が実測された日に問い直す。

UI については収穫が無かった。参照元のグラフ描画は実行DAGの可視化であり、
tomobit の分割・比較・経験の表示には移す理由がない。**逆に、ツール出力の表示予算・
台帳と表示の分離・不明値の表示・並走子の相関は、既に tomobit 側にある。**

## Consequences

- **データは一切取り込まない。** モデル能力データの汚染経路を心配する必要すらない —
  tomobit の Provider は CLI であり、モデル能力データベースに該当データが無い
- **AGPL §13 は本ADRで新規に発生しない。** ネットワーク越しに使わせるなら対応ソースの
  取得導線が要るが、それは外部実装の参照とは無関係に元から負っている義務である
- **残る不確実**: 参照元の全ファイルが例外なく MIT かは未検査である。ルートの LICENSE と
  各 `pyproject.toml` の宣言までしか確認していない。ファイル単位のヘッダ、第三者由来の
  混在、CLA は見ていない。**Decision 1 を守る限りこの不確実は無害**になる — 表現を
  持ち込まないなら、その表現が誰のものかを確定させる必要が無いからである
- 却下: `THIRD_PARTY_NOTICES.md` の予防的設置。「念のため」は、翻案していないという
  主張を自分で薄める
- 却下: 参照元を読まずに設計する（完全な clean room）。読まなければ Decision 4 の
  「採らない」7件も判定できない。**読むこと自体は問題ではない。持ち帰るものが問題である**
- 本ADRは法的助言ではない

---

## 原則

> **借りるのは発想だけ。表現を借りたら、名前を書く。**
>
> 発想に許諾は要らない。だからこそ、どこまでが発想かを自分で線引きしておく。
