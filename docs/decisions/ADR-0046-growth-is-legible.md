## Context

所有者の実感は二つの層でできている:

> 成長が早くて、気がついたらもう「おとな」になっているため、**育てている感覚にならない**

前半（速すぎる）は ADR-0045 がゲートの側で扱う。しかし後半は、ゲートを
正しくしただけでは解けない。**進捗が一切見えないから**である。

今日、成長について使用者が受け取れる情報は二つしかない:

- 顔窓のスプライト（段が変わると姿が変わる）
- `voice.Growth` の一言（段が**変わった瞬間だけ**「少し育った気がする」）

つまり **段が変わるまで、何も見えない**。しかも実測（ADR-0045 Context）では
3つのゲートが同一セッションで同時に開き、こども と わかもの は一度も
観測されないまま「おとな」に着地していた。使用者から見れば、
**育てた覚えのないものが、いつのまにか育っている**。

育成の実感は「今どこにいて、次に何が足りないか」が見えることで生まれる。
その情報は既に全部**導出済み**である — `StageFrom` は maxEvidence・
較正平均・島ごとの Wobble・preference Evidence を計算しており、
どのゲートで止まっているかを知っている。**知っているのに、捨てている。**

これは ADR-0040 が `tomo.decided` について見つけたのと同じ構図である
（「相棒が答えられるのに黙っている」）。同じ解き方をする。

## Decision 1: `status --view json` に `growth` を足す

`StageFrom` が段を決めるときに評価した各ゲートを、値・閾値・充足の三つ組で
そのまま流す。

```json
{"type":"status","exists":true,"stage":3,"stage_name":"わかもの",
 "growth":{
   "next":4,"next_name":"おとな",
   "gates":[
     {"name":"evidence","value":22.10,"threshold":3.0,"met":true},
     {"name":"calibration_sample","value":31.2,"threshold":8.0,"met":true},
     {"name":"calibration","value":0.07,"threshold":0.15,"met":true},
     {"name":"sharpness","value":0.49,"threshold":0.2,"met":false,
      "hint":"duelや質問に答えて好みを教える"}]}}
```

- **view のために新しい計算はしない**（ADR-0040 Decision 1 と同じ規律）。
  `StageFrom` が段を決める過程で既に出している値を、捨てずに返すだけ。
  そのために `StageFrom` の内部を「ゲートの評価結果を返す」形に組み直す
  （段そのものは評価結果から導出される。**ステージが View であることは不変** —
  ADR-0008 Decision 1、保存しない）
- **列挙するのは `next` に到達するために要るゲートだけ**。ゲートは累積なので
  next=4 なら evidence・較正・鋭さ、next=5 ならそれに human ペアの preference が
  加わる。上の例（わかもの）に `preference_with_human` が無いのはそのため —
  それは S5 のゲートであって「次の段（おとな）に足りないもの」ではない
- **毛玉(S0)の next ゲートは `connection`（connection の誕生・閾値1）であって
  evidence ではない**。実条件は最初の connection が生まれること（最初の仕事1回で
  孵る）なので、evidence≥3 の開示は偽の遠さ — 偽の進捗を見せないことの裏面
- **較正は2つのゲートに分ける**（`calibration_sample` と `calibration`）。
  `isCalibrated` は「標本が足りない」と「予測がズレている」という**別の理由**で
  落ちるのに、1つの数字ではどちらか分からない。Decision 3 の表もこの2つに
  別の「次の一手」を割り当てている
- 満たせないゲートが「なぜ満たせないか」を値が語る形にする。特に ADR-0045
  Decision 1 の「競争のある島が無い」は、**閾値との比較では表せない**
  （測定不能であって未達ではない）。この場合は値を null とし、
  測定不能であることが読み手に分かる形にする — **未達と未定義を同じ顔にしない**
- 段が最上位（あいぼう）のときは `next` を持たない。上がない状態を
  「達成率100%」のような偽の進捗で埋めない

## Decision 2: 声は変えない。見せ方はレンダラの裁量、既定は畳む

ADR-0040 Decision 2 と同じ二層に置く。

- `voice.Growth`（段が変わったときの一言）は**今のまま**。ADR-0015 が
  「語る器官は Reflection だけ・数表を読み上げる相棒は相棒ではない」と
  定めた線は越えない
- GUI は既定では今までどおり段と表情だけを見せる。**開いた者にだけ**
  「次は おとな。足りないのは鋭さ（0.49 → 0.2以下）」が見える
- 端末の `status` にも既定では出さない。端末は声の場（ADR-0025）で、
  監査したい者には機械 view がある

## Decision 3: 足りないものは、次の一手に翻訳して見せる

数値だけでは「何をすればいいか」が分からない。ゲートごとに、**その値を
動かす行為**を一行で添える。文言は Go のテンプレート（LLM を使わない —
ADR-0007 Decision 4 と同じ流儀）。

| ゲート | 足りないとき添える一手 |
|---|---|
| evidence / calibration_sample | もっと一緒に仕事をする |
| calibration（ズレている） | 予測が外れている文脈がある |
| calibration（台帳が空で平均が未定義=null） | もっと一緒に仕事をする（標本の問題であってズレではない） |
| sharpness・競争なし（null） | **二人目の Provider に会わせる**（ADR-0043 の auto に任せる） |
| sharpness・迷っている | duel や質問に答えて好みを教える |
| preference_with_human | 自分でやった仕事を Tomo に見せる（`--provider human`） |

一手は満たせないゲートにだけ `hint` として機械 view に同乗させる（充足した
ゲートに一手は無い）。翻訳表を本体が持つことで、レンダラが表を手移植して
ドリフトする余地を残さない（ADR-0039 と同じ規律）。

これは指示ではなく開示である。**「やってあげる」ではなく「判断できる材料を渡す」** —
どれを選ぶかは使用者が決める。

## 却下した対案

- **進捗バー（次の段まで何%）を出す** → 4つのゲートは単位も意味も違い、
  合成した一つの数字は**意味の無い数字**になる。かつ「あと20%」は
  達成が近いという嘘をつきうる（ゲートは AND で、一つでも欠ければ0%と同じ）
- **段の履歴を保存して成長曲線を描く** → ADR-0008 Decision 1（ステージは
  保存しない・View である）を破る。同じ台帳から同じ顔が出ることが、
  ステージが導出値であることの担保になっている。曲線が欲しければ
  台帳から再導出できる（`tools/dogfood/replay/stagecurve` が実際にやっている）
- **`voice` に「あと少しで大人だよ」と言わせる** → ADR-0015 Decision 4 に反する。
  加えて、ゲートは非単調（減衰で下がる）ので、「あと少し」は撤回されうる約束になる
- **専用サブコマンド `tomobit growth`** → 器官を増やす。`status` は既に
  「今どうなっているか」を答える場所である

## Consequences

- `internal/face` の `StageFrom` が、段だけでなく**評価の内訳**を返す形に変わる。
  既存の呼び出し側（顔窓・`status`・chat）は段だけを見ればよいので、
  戻り値の追加であって破壊ではない
- `status --view json` に `growth` が増える。ADR-0032 Decision 1 の前方互換
  契約により、旧 GUI は黙って無視する
- GUI に開示UI（既定は畳む）。ADR-0040 の provider チップ展開と同じ作法で置く
- 「測定不能」と「未達」を区別する表現が、機械 view と GUI の両方に要る。
  ADR-0045 Decision 1 が作った状態（競争のある島が無い＝鋭さは未定義）を
  **正直に表示できることが、本ADRの実装の合否**である
- テスト: (1) 各ゲートの値が `StageFrom` の判定と一致する (2) 測定不能が
  null で出る (3) 最上位で `next` が出ない (4) 声が不変 (5) 同じ台帳が
  常に同じ `growth` を返す（View 性）
