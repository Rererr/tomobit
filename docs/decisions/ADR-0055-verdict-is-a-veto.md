## Context

ADR-0003 は Outcome を三層に分けた。第1層（客観・毎回）、第2層（明示判定・任意）、
第3層（好み・訊かれた時）。第3層は duel（ADR-0026）が、第1層は ADR-0052 が書き手を
生やした。**第2層 `user.verdict` だけが、初期カタログ（SCHEMA R4）に載ったまま
6年間書き手を持たない。** 実台帳でも 0 件である。

### なぜ今まで要らなくて、なぜ今要るのか

第2層は「強い上書き」で、`OutcomeWeight` は Verdict を**最初に**読む。導出の順序を
縦に並べる:

```text
Cancelled                → 無効      機械   何よりも先（判定する成果物が無い）
Verdict up/down          → 1 / 0    人     ← 第2層（空席）
Reverted（3=だめだった）   → 0        人
TestsPassed=false        → 0        機械   ★
Adopted as-is（1=文句なし）→ 1.0      人
Adopted with-edits       → 0.7      人
Failed（provider.error）  → 0        機械   ← as-is より下（既に人が勝つ）
TestsPassed=true         → 0.9      機械
```

★は、**この導出全体で唯一、機械が人より上に立つ場所**である。`provider.error` は
既に `as-is` に負ける（ADR-0003 の実装注記: 人の主権が一過性のエラーに勝つ）。
緑テストは人の答えが無いときの補完でしかない。3=だめだった は赤テストと同じ向き
なので衝突しない。

`test.result` が 0 件だった間、★は発火しようがなく、上書きすべき対象が存在
しなかった。**第2層が空でも誰も困らなかったのは、第1層も空だったからである。**
ADR-0052 が第1層に書き手を生やした瞬間、「テストは赤いが、この仕事は良かった」
と言う道の不在が、初めて実害になった — テストコマンドが的外れだった日、テスト自体が
壊れていた日、`1=文句なし` は黙って y=0 に潰される。

**第2層は、機械の観測に対する人の拒否権である。** 経験主権（ADR-0018）の側から
言えば: 観測は人の判断の材料であって、人の判断の上位ではない。

### 台帳が示していること（2026-07-27 実測）

```text
1=文句なし               15
3=だめだった              2
2=まあまあ                1
Enter=まだ言えない         8   ← 訊かれた26回のうち31%
（分割の子の無回答 12 は ADR-0054 でそもそも訊かない側に確定）
```

「まだ言えない」が 8 件ある。ADR-0051 は「Enter には重ねて訊かない」と決めた
（正しい — 言えないと言った人を問い詰めない）。だがそれは、**後で言えるように
なった時の受け皿が無い**ということでもある。1週間後に「あのリファクタは壊れていた」
と分かる日は来る。ADR-0003 が第2層に書いた「気が向いた時」は、この受け皿を指す。

## Decision 1: 書き手A — 境界で、矛盾した時だけ訊く

境界の Feedback で **`test.result` が赤 かつ 答えが `1=文句なし`** のとき、
1問だけ追加する:

```text
テストは赤だったけど、文句なし？
y なら、この答えは赤より強く記録される [y/N]
```

- **y** → `user.verdict {verdict:"up"}` を追記。境界の知覚（この直後に走る）が
  `parseDeterministic` で読み、経験の Verdict になる — **新しい知覚機械はゼロ**。
  `case "user.verdict"` は初版から実装されている
- **N / Enter** → 何もしない。沈黙は同意ではない（ADR-0049）ので、既定は
  「上書きしない」。赤が立ち、y=0 になる — ただしそれは**人が明示的に拒否権を
  使わなかった上での y=0** であり、答えの曖昧さはどちらに転んでも解消される
- 問いは `recordSplitVerdict`（ADR-0051）の隣、Feedback の答えを読んだ直後に走る。
  経路も同じ境界チャネル（ADR-0032 の view 契約に乗る）なので GUI も同様に通る
- `observeFirstLayer` は Feedback の**前**に走る（ADR-0052 Decision 5:
  「赤いスイートは、採点する人が持っているべき事実」）。つまり人は**赤を見た上で**
  文句なしと答えており、この問いは後出しの藪から棒ではなく、いま画面に並んでいる
  2つの事実の矛盾への確認である

### トリガーは `1=文句なし` だけ（所有者決定 2026-07-27）

赤テスト × `2=まあまあ` も形式上は矛盾する（0.7 が 0 に潰される）が、**含めない**。
「手を焼いた」と自分で言った日の赤は、拒否権を訊くほど鋭い矛盾ではない。
ADR-0051 が「摩擦は結果に比例」で通した線をここでも守る — 矛盾が鋭い時だけ、1問。

### 観測は消さない。判定で上書きする

y と答えても `test.result` は赤のまま台帳に残る。経験の行の中で
`TestsPassed=false` と `Verdict="up"` が**共存**し、導出時に強い方が勝つ。
機械の観測を人の答えで書き換える経路は作らない — 観測は観測として真実であり
（テストは実際に赤かった）、それをどう裁くかが判定である。

### ADR-0003 の哲学との一致

第2層を「常設コマンドを覚えて使う」形にしないのは、ADR-0003 Decision 3 が
「ラベリング義務を pull 型に反転させる」と書いたからである。矛盾の瞬間は
`OutcomeWeight` の順序表から**1点に特定できる**のだから、その瞬間に tomobit の
方から訊けばよい。学習コストはゼロ — コマンドの存在を知らなくても、矛盾した
瞬間に口が現れる。

## Decision 2: 書き手B — `tomobit verdict <sid> up|down|clear`

閉じたタスクへの、後からの判定。「まだ言えない」の受け皿であり、
「1週間後にゴミだと分かった」の口である。名前は ADR-0006 Decision 3 が
「将来の verdict コマンド」として予約したものをそのまま使う。

```text
tomobit verdict <session-id> up      👍 — この仕事は良かった（y=1 で上書き）
tomobit verdict <session-id> down    👎 — この仕事はだめだった（y=0 で上書き）
tomobit verdict <session-id> clear   取り消し — 無意見に戻す（第1層へ落ちる）
```

動きは5段:

```text
1. 断る:  task.finished を持たない   → まだ終わっていないタスクは判定できない
          task.cancelled             → 判定する成果物が無い（OutcomeWeight 自身の扱い）
          分割の子                    → 経験を持たない（ADR-0054。duel の子は独立した
                                        発注なので判定できる — ADR-0026）
          user.amended 済み           → 人間の知覚は最終知覚（ADR-0033 D4）。amend を案内
2. user.verdict {verdict} をそのセッションに追記
3. 経験がまだ無ければ（境界の知覚が失敗して保留列に居る）ここで終わり —
   保留列が拾う時に parseDeterministic が普通に読む
4. 経験があれば: 現行の execution 行を extractor_ver+1 で1行コピーし、
   Verdict だけ差し替える
5. 自動 rebuild（ADR-0033 Decision 2 と同じ規律 — 射影整合を人の手順にしない）
```

### イベントが真実で、コピーは「今効かせる」ためだけ

設計の要はここにある。`user.verdict` を**イベントとして**積む以上、以後のどの
再知覚（extractor 改版）も `parseDeterministic` がそれを読み直す。**判定は不滅で
あり、コピーが運んでいるのは永続性ではなく即時性だけ**である。

このため、copy-forward が生む世代番号の副作用は小さい:

- セッションの版 == 機械の版のとき（通常）: コピーが ver+1 を先取りするので、
  **次の1回の改版でだけ意味の更新が飛ぶ**。その次の改版で追いつき、判定は
  イベントから再読される。失われるものは無い
- セッションの版 < 機械の版のとき: コピーの ver+1 が機械の版に届かず、
  次の `perceive` で普通に再知覚される。スキップ自体が起きない

### 1行で済む理由

amend（ADR-0033）が同 (session, kind) の現行世代を**全行** copy-forward するのは、
`experiences_current` が (session, kind) ごとの最大版を選ぶためである。だが view は
**kind 単位**であり、execution 行はセッションに**1行**しかない（`perceiveSession` は
execution を1件だけ作る）。preference の兄弟は別 kind なので巻き込まれない。
verdict の copy-forward は execution 1行のコピーで完結する。

### 確認ゲートは置かない

forget が y/N を要るのは不可逆だから（ADR-0033）。verdict は追記+新世代で、
`clear` で戻せる。可逆な操作に儀式を足さない。

### 判定の重ね書きは「最後が勝つ」

`parseDeterministic` はイベントを順に読んで代入するので、後の `user.verdict` が
前を上書きする。台帳には両方残る（判定を変えたこと自体が Reality）。
`clear` はイベントとしては `{verdict:"clear"}` と人の言葉のまま記帳し、
`parseDeterministic` が `""` へ写像して行を up/down/空 の語彙に保つ
（`OutcomeWeight` は up/down 以外を無視するので、写像を忘れても壊れはしない —
写像は行の語彙の清潔さのため）。

`parseDeterministic` へのこの1行追加に extractor_ver のバンプは不要:
`user.verdict` は実台帳に0件なので、既存セッションの知覚は1つも変わらない
（ADR-0006 の「抽出プロンプト/schema 不変ならバンプ不要」と同じ理屈の適用）。

## Decision 3: verdict は判定だけを差し替え、凍結しない — amend との分業

|          | amend                          | verdict                        |
|----------|--------------------------------|--------------------------------|
| 対象     | **知覚**（意味も判定も）        | **判定だけ**                    |
| 機構     | (session,kind) 現行世代を全行   | execution 1行                  |
| 出自     | `human` に書き換え              | **元のまま**                    |
| 凍結     | する（`user.amended` → D4）     | **しない**                      |
| 取消     | 再 amend のみ                   | `clear` で戻せる                |

`extractor_model` を書き換えないのは手抜きではなく正確である: 経験の行のうち
**モデルの主張は context だけ**で、outcome は最初から `parseDeterministic`
（決定的コード）の領分である。判定を差し替えてもモデルの主張には1バイトも
触れていないのだから、出自表示を変える方が嘘になる（ADR-0033 の
「出自は嘘をつかない」の適用）。

凍結しないのも同じ理由から出る。ADR-0033 D4 の凍結（`user.amended` を持つ
セッションは再知覚しない）が守っているのは「人の訂正を機械が『より良い解釈』で
上書きする」事故である。verdict は機械が知覚した意味に触れないので、守るべき
訂正がそもそも存在しない。むしろ凍結**してはいけない** — 👍 を1つ付けた代償に
そのセッションが将来の抽出器改善を全て失うのでは、拒否権の行使に税金がかかる。

使い分けの一言: **「後で言えるようになった」は verdict、「意味の取り方が
間違っていた」は amend。** 動詞の役割が重ならない（ADR-0033 Decision 2 の線の延長）。

## 却下した対案

### chat 内 `/verdict`（開いているタスクへの常設コマンド）

起草者の初案。却下する。開いているタスクへの判定は、成果物が完成していない時点の
判定で、**構造的に時期尚早**である（ADR-0007 が問いを境界に置いたのと同じ理由）。
そして「赤への拒否権」が要る瞬間は第1層が走った**後** — 境界（書き手A）か、
その後（書き手B）— なので、タスク中の口はどの実需要にも当たらない。

### イベントだけ積んで、効くのは次の改版から

書き手Bから copy-forward を省ける最小案。却下する。👍 を押しても何も変わらない
器官は、`test.result` が0件のまま6年眠ったのと同じ死に方をする。効果が
extractor 改版（数ヶ月来ないかもしれない）まで宙吊りになる器官は、無いのと同じ。

### 経験行を直接 UPDATE する

不可能である。experiences は append-only（トリガーで UPDATE/DELETE を拒否）。
これは制約ではなく設計で、だからこそ copy-forward という形が forget/amend と
共通の語彙になっている。

### 射影が events から verdict を直接読む

Rebuild が experiences ではなく events を join する形。却下する。
「events → 知覚 → experiences → connections」の管の形が壊れ、
「Split 直後の子の (α,β) == 同じ経験からの rebuild」という不変量も壊れる。
経験が学習の材料である、という One Ledger の投影構造は動かさない。

## Consequences

- **SCHEMA R4 の `user.verdict` に、初めて payload の形が定義される**:
  `{verdict: "up"|"down"|"clear"}`。初期カタログに載って6年、形の無かった型が閉じる
- **書き手Aは `test_commands` が配線されるまで休眠する。** これは欠陥ではなく連動 —
  第2層は第1層への拒否権なので、第1層が眠っていれば眠っているのが正しい
- **書き手Bは即日効く。** 「まだ言えない」で閉じた8セッションがそのまま初期在庫
- **世代番号の意味が少し濁る**: copy-forward の ver+1 は特定の抽出器コード版に
  対応しない番号になる（amend が既に踏んでいる道であり、新しい濁りではない）
- **書き手Bの入口は sid で、CLI では遠い。** GUI のタスク一覧に 👍/👎 が並んで
  完成、という見立てを隠さない — それは tomobit-gui 側の後続フェーズであり、
  本ADRの範囲は本体の2つの書き手まで
- **質問予算（ADR-0003 の1日1問）には触れない。** 書き手Aは Curiosity の質問では
  なく境界の器官の追加質問で、ADR-0051 と同じ側に立つ
- **索引 / SCHEMA / 関連ADRへの追記は Accepted 時**（プロジェクトの規律どおり）

## 実装フェーズ（Proposed）

1. **書き手B**: store に execution 1行の copy-forward、`cmd/tomobit` に verdict
   コマンド（拒否条件・イベント追記・自動 rebuild）。`parseDeterministic` の
   `clear → ""` 写像。ここまでで第2層は生きて即日使える
2. **書き手A**: `finishTask` の矛盾フォローアップ（`recordSplitVerdict` の隣）。
   境界チャネル経由で GUI からも答えられることを確認
3. **（別リポ・後続）** tomobit-gui のタスク一覧から書き手Bを呼ぶ口

各フェーズ末に使い捨て台帳での通し確認を含める（実台帳とそのコピーは検証に使わない）。
