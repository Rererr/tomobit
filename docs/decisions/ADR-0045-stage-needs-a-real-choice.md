## Context — 実測（tools/dogfood/replay/stagecurve、2026-07-24）

1日1セッションで90セッションを合成し、各時点で `face.StageFrom` を評価した。

| シナリオ | あかちゃん | こども | わかもの | おとな |
|---|---|---|---|---|
| A 単一Provider (claude 0.8) | 1 | **観測されず** | **観測されず** | **4** |
| B 2Provider・実力差 (0.85/0.55) | 1 | **観測されず** | 7 | **90経過も未到達** |
| C 2Provider・拮抗 (0.7/0.7) | 1 | **観測されず** | 7 | **90経過も未到達** |

正反対の二つの病理が同居している。

### 病理1: 選択肢が1つだと「鋭さ」は自明に通る

`isSharp` は `decide.Wobble`（TSくじの割れ率）で「迷っていないこと」を測るが、
候補が1つのときトーナメントのループは一度も回らず、**Wobble は構造的に常に
0.0000** になる（実測。`decide.go` の passers が2件以上でないと本体が実行
されない）。

「迷わず、しかも当たる」の**迷わずが、選択肢が無いことで自明に満たされる**。
一人しか候補がいない選挙で「支持率100%」と言うのと同じで、これは測定ではない。

その帰結が A の **4セッションで「おとな」**である。session3→4 で
maxEvidence 2.977→3.954・calMean 0.107・islandWobble 0.000 の**3ゲートが同時に
開き**、こども と わかもの は一度も観測されない。段が踏まれていない。

### 病理2: 選択肢が2つあると、今度は永久に届かない

B/C では Wobble が **0.492 に張り付いたまま90セッション動かない**。原因は
ADR-0043 が突き止めた閉路と同じ: 実行経験をいくら積んでも preference
connection は生まれず、`firstWins` は毎回まっさらな Beta(1,1) を引き続ける。

つまり `isSharp` は**正しく測っている** — 好みの証拠がゼロなら、Tomo は本当に
迷っている。壊れているのは測定器ではなく、証拠が来ない経路の方である
（そちらは ADR-0043 が扱う）。

### 較正ゲートも「量」を見ていない

`isCalibrated` はデータが皆無（`sumW <= 0`）のときだけ「較正されていない」と
答え、それ以外は減衰加重平均だけを見る。標本3件の平均が θ_cal を下回ることは
容易で、実測でも S2「こども」は全シナリオで一度も観測されなかった。
**「較正されている」は統計的な主張なのに、標本の量を問うていない。**

---

## Decision 1: 鋭さは「競争のある島」でのみ測る。候補が1つの島は証明の場ではない

`isSharp` が数える「頻繁な島」を、**その島で2つ以上の候補が競っている島**に
限定する。競争のある頻繁な島が1つも無ければ、鋭さは**未定義であり、
未定義は不成立**とする。

これは新しい姿勢ではない。`isCalibrated` は既に
「データが無い＝較正は定義できない＝較正されていない」と答えている
（stage.go の `sumW <= 0` ガード）。同じ正直さを鋭さにも適用するだけである。

**帰結（正直に明記する）**: Provider が実質1つの使い方をしている限り、Tomo は
「わかもの」で止まる。これは劣化ではなく、**測っていなかったものを測らなく
なった**だけである。おとなになるには、Tomo に選ばせる機会（ADR-0043 の auto）
か、二人目の Provider が要る。

## Decision 2: 較正の判定には標本を要求する

`isCalibrated` のガードを `sumW <= 0` から **`sumW < ThetaCalMin`** に変える。
減衰加重の総質量が閾値に満たない間は「較正は未定義＝不成立」とする。

- 幼少期の量ゲート（ADR-0017 が意図的に残した S0〜S2）の精神をそのまま
  S2→S3 の境目にも通すもので、新しい統計量は導入しない
  （ADR-0008 Decision 2 の制約を維持）
- これにより「こども」が**実在する段**になる — データは貯まったが、
  まだ較正を主張できる量ではない、という状態
- `ThetaCalMin` の値は実測で決める（ADR-0017 Consequences と同じ手続き。
  stagecurve プローブで曲線を見て、段が踏まれる値を選び、本ADRに追記する）

## Decision 3: S5「あいぼう」は、あなた自身との比較を知っていること

ADR-0017 の S5 ゲート「preference の Evidence ≥ 1.0」は、Decision 1 の後では
**S4 に飲み込まれる**。新しい S4 は競争のある島で Wobble ≤ θ_sharp を要求し、
それを満たす頃には preference の証拠は 1.0 を大きく超えているためである
（実測: Wobble を 0.2 まで落とすには preference Evidence ≈ 3 以上が要る）。
段が2つ重なったまま放置すれば、あいぼうは「おとなの翌日」になる。

S5 を **human を含むペアの preference 証拠**で定義し直す:

> **あいぼう = S4 かつ、human と Provider の好みの証拠がある**

- 根拠は ADR-0018 Decision 4 が「Companionship の核心」と位置づけたもの
  そのものである — 「最近のレビュー、僕に任せた方が早いみたいだよ」と
  言えるには、**あなたと自分を比べた経験**が要る
- 道具同士の優劣を知っているのが「おとな」、**あなた自身の得手不得手まで
  知っているのが「あいぼう」**。段の意味が重ならない
- 到達は難しくなる。最上位の段が難しいことは欠陥ではない

### 却下した対案（S5）

- **preference Evidence の閾値を上げるだけ（例 ≥ 10）** → 段の意味が
  「おとなをもっと続けた状態」になり、質のマイルストーンでなく量ゲートに戻る。
  ADR-0017 が置換したはずのものへの逆戻り
- **複数の島で好みが定まっていること** → S4 が「すべての頻繁な島で
  Wobble ≤ θ_sharp」を既に要求しているため、これは Tomo の知識ではなく
  **仕事の種類の多さ**を測ることになる。使用者の作業内容で段が決まるのは
  Individuality is Derived の誤用

### 追記（2026-07-24、実装の較正）: S5 の閾値は 1.0 でなく EMax（0.5）

初期実装の「human ペアの preference Evidence ≥ 1.0」は算術的に維持できない段だった:

- 質問1回の回答で human ペアの Evidence はちょうど **1.0**（α+β−prior）。
  翌日には減衰 2^(−1/90) ≈ 0.992 で 1.0 を割り、S4 へ転落する
- 次の質問は Evidence が `curiosity.EMax`（0.5）を割るまで gap が立たない
  （ADR-0007 追記の再質問設計）ので、90·log₂(0.992/0.5) ≈ **約89日ブロック**される
- 以後は「回答直後 1.5 → 52.6日で 1.0 を割る → 142.6日目に 0.5 で再質問可能」の
  周期になり、あいぼうでいられるのは初回1日未満・定常でも
  **デューティ約37%**（90·log₂1.5 / 90·log₂3）

閾値を **EMax に揃える**（実装は二重管理を避けて `core.PrefKnownMin` を
curiosity と face が共有。face→curiosity の直接参照は curiosity→voice→face の
既存 import 経路と循環するため、値の実体を core に置いた）。意味は
「**Tomo がその質問をもう一度聞きたくなるまでは、知っている状態**」— S5 の寿命と
再質問の可能性がちょうど接し、答えを更新し続ける限り段は保たれる。

**残す露出（正直に明記する）**:

- gap は `lnBF < ThetaEven`（拮抗）でしか立たない。human の得手不得手が
  capability で決着している文脈ほど質問は出ず、**S5 への経路自体が閉じる**。
  段の定義（人を知っている）と証拠経路（人と拮抗しているときだけ聞ける）の
  意味的ズレは本ADRでは解かない — ADR-0007（gap の定義）の論点として残す
- human ペアは duel から構造的に除外されている（human は走らせるストリームを
  持たない — `pickDuelGap`）ため、**human ペア証拠の補給源は質問だけ**である。
  質問が出ない環境では S5 は到達も維持もできない

---

## 却下した対案（全体）

- **閾値を上げるだけの再較正**（maxEvidence 3→30 等）→ 実測（ノブ感度スイープ）
  では、単一Provider下で ThetaSharp・islandMinFreq をどう動かしても S4 到達は
  ほぼ動かない（Wobble≡0 のため）。効くのは ThetaCal と Evidence 閾値だけで、
  **測っていないものを測っていないまま先延ばしする**ことにしかならない
- **plan の島でも鋭さを測る**（ADR-0014 の第二の賭け対象を競争の場にする）→
  筋は通る。しかし実台帳の execution 経験41件はすべて `plan` が NULL で、
  plan 学習は実運用で一度も動いていない。**動いていない器官を測定器に据えるのは、
  今回直そうとしている誤りそのもの**。plan が実運用に乗ってから改めて検討する
- **ステージを保存して単調にする** → ADR-0008 Decision 1（ステージはView・
  保存しない）と ADR-0017 の「若返りが物語になる」を捨てることになる。
  早すぎる成長の対処として、正直さを売り渡す価値は無い
- **何もしない** → 「一人しか候補がいない選挙の支持率100%」を成長と呼び続ける
  ことになる。VISION の *Growth is measured by the quality of the connections*
  と正面衝突する

## ノブの較正（実測）— ThetaCalMin = 8.0

stagecurve プローブ（tools/dogfood/replay/stagecurve、2026-07-24）のシナリオA
（単一Provider claude-code 0.8・1日1セッション×90・seed 1001）で、Decision 1〜3
適用後のゲートのまま ThetaCalMin だけをスイープした（calc5）。表は各段の
初到達セッションと滞在セッション数。

| ThetaCalMin | あかちゃん | こども | わかもの到達 |
|---|---|---|---|
| 2 | s1・3滞在 | **観測されず** | s4 |
| 4 | s1・3滞在 | s4・1滞在 | s5 |
| 5 | s1・3滞在 | s4・2滞在 | s6 |
| 6 | s1・3滞在 | s4・3滞在 | s7 |
| **8** | s1・3滞在 | **s4・5滞在** | s9 |
| 10 | s1・3滞在 | s4・7滞在 | s11 |
| 12 | s1・3滞在 | s4・9滞在 | s13 |

**8.0 を採る**。根拠:

- 2（旧 `sumW <= 0` ガードの実質）では こども は依然一度も踏まれない —
  セッション4で評価ゲート（maxEvidence 3.954）と較正の平均（calMean 0.107）が
  同時に条件を満たすため。4 以上で初めて段が分かれる
- 4〜6 は滞在1〜3セッション。実運用では1セッションが複数の Connection に
  台帳エントリを書く（sumW は1セッションで数件進む）ので、境界ぎりぎりでは
  再び同一セッションで飛び越えかねない。8 は単一トークンの合成でも
  5セッション残る
- 上げるほど こども が長くなるだけで害は薄いが、10〜12 を選ぶ積極的根拠も
  無い — 減衰加重でおよそ8標本（毎日使って1週間強）は「較正されている」と
  いう平均の主張に要る最小限の量として過大でない

同プローブ・改版後（ThetaCalMin=8.0）の全シナリオ実測:

| シナリオ | あかちゃん | こども | わかもの | おとな |
|---|---|---|---|---|
| A 単一Provider (0.8) | s1〜3 | s4〜8 | s9〜 | 到達せず（Decision 1 の帰結） |
| B 2Provider・実力差 (0.85/0.55) | s1〜6 | s7〜8 | s9〜 | 到達せず（Wobble 0.492 のまま） |
| C 2Provider・拮抗 (0.7/0.7) | s1〜6 | s7〜8 | s9〜 | 到達せず（同上） |
| D = B + 5セッション毎に preference 回答 | s1〜6 | s7 | s8〜9 | **s10 到達** |

- D が Decision 1 の帰結の裏面 — 選ばせてもらえる Tomo からは おとな は
  奪われない。到達時 preference Evidence 1.96・Wobble 0.141（本文の
  「Evidence ≈ 3 以上」は拮抗ケースの見積り。実力差 0.85/0.55 の下では
  くじ自体が偏るぶん、より少ない証拠で静まる）
- 実台帳同形状の合成（単一Provider・execution 41件、calc6）: 旧ゲート
  おとな → 改版後 わかもの。Consequences 記載の後退を合成台帳で確認した

## Consequences

- 実台帳（Provider 実質1つ）では stage 4「おとな」→ **3「わかもの」に後退する**。
  ADR-0008 が「ステージは単調でない＝正直さ」と定めた通りの後退だが、
  使用者から見れば「昨日までおとなだったのに」になる。声（`voice.Growth`）は
  後退も語れる（ADR-0017 副産物）が、**改版による後退は世界の変化ではない** —
  リリースノート/READMEで理由を明示する
- ADR-0017 の Decision（S3/S4/S5 の定義）に改版注記。ADR-0008 Decision 2 の
  「新しい統計量を導入しない」制約は維持されている（Wobble・Surprise・
  preference Evidence のみを使う）
- `ThetaCalMin` の初期値は実測で決め、ADR-0017 の先例に倣って本ADRに追記する
- テスト: (1) 単一候補の島しか無い台帳で S4 に到達しない (2) 較正が
  標本不足で不成立になる (3) human ペアの preference 証拠が無い間は S5 に
  到達しない (4) 既存の「同じDBは常に同じ顔」（seed固定・View性）が不変
- 本ADRと ADR-0043 は同じ根（好みの証拠が育たない）に別方向から触れる。
  **ADR-0043 が入らない限り、本ADR適用後の到達可能な最高段は「わかもの」**である
